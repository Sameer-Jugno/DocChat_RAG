================================================================================
DOC CHAT (DocChat_RAG) — COMPLETE APPLICATION UNDERSTANDING
================================================================================
Location: DocChat_RAG/ (GitHub)
Purpose: Upload ONE document, index it, then chat with grounded answers and
         text citations (text RAG only).

Note: The local sibling folder `pdf-chat/` retains optional CLIP figure-page
      retrieval. This GitHub project does not.


--------------------------------------------------------------------------------
1. PRODUCT SUMMARY
--------------------------------------------------------------------------------

Job to be done:
  "I have a document. I want to ask questions and get answers grounded in that
   document, with citations."

Scope (v1):
  - One file at a time (new upload replaces the previous index)
  - Formats: .pdf, .txt, .md/.markdown, .csv, .docx
  - PDF: native text + OCR for scanned/low-text pages
  - Chat UI: Chainlit
  - Optional REST API: FastAPI

Not in scope:
  - Multi-doc libraries / multi-user auth
  - Legacy .doc, Excel (.xlsx), standalone image uploads as primary docs
  - Cloud vector DB / rerankers
  - CLIP / figure-page image retrieval (see local pdf-chat/)
  - Perfect OCR

--------------------------------------------------------------------------------
3. END-TO-END FLOWS
--------------------------------------------------------------------------------

3.1 Upload / Ingest
  1. User opens Chainlit → chat bar locked until upload (AskFileMessage).
  2. File saved under data/uploads/.
  3. extract_document() loads text by file type.
  4. Text is chunked (~1200 chars, 150 overlap) with page/section/row metadata.
  5. Text chunks embedded with sentence-transformers/all-MiniLM-L6-v2.
  6. Qdrant text collection is reset and refilled (replace semantics).
  7. UI unlocked for chat.

3.2 Ask a text question
  1. Embed question with MiniLM.
  2. Retrieve top-k text chunks from Qdrant.
  3. Build prompt: system rules + trimmed chat history + context + question.
  4. Stream answer from Groq.
  5. Append **Sources** as plain text at end of the reply.
  6. No side-panel resource widgets.


--------------------------------------------------------------------------------
4. SUPPORTED FORMATS
--------------------------------------------------------------------------------

  Extension     Extraction                         Citation unit
  -----------   --------------------------------   --------------
  .pdf          pypdf text; OCR fallback           page (p.N)
  .txt          UTF-8 text, sectioned              section (sec.N)
  .md           UTF-8 markdown, sectioned          section (sec.N)
  .csv          header + row groups (~25 rows)     rows (rows.N)
  .docx         paragraphs + tables (python-docx)  section (sec.N)

PDF OCR:
  - RapidOCR (onnxruntime) — no system Tesseract required
  - Used when a page has little native text (< OCR_MIN_CHARS)
  - Optional OCR of large embedded images on text-heavy pages (text only)

6. KEY MODULES (WHAT EACH DOES)
--------------------------------------------------------------------------------

app/config.py
  - Loads .env
  - Groq, Qdrant, embedding models, chunk sizes, OCR flags
  - upload_max_mb property for size limits

app/ingest/loader.py
  - Dispatches by extension
  - PDF path: native text → page OCR if sparse → optional image OCR append

app/ingest/pipeline.py
  - Size/type checks → extract → chunk → reset text index → upsert

app/rag/chat.py
  - Text retrieve (MiniLM)
  - Groq answer streaming
  - Sources returned to UI for text footer

app_ui.py
  - Welcome + AskFileMessage (locks composer until upload)
  - Indexes file, unlocks chat
  - Streams answer
  - Appends Sources as trailing markdown text
  - /upload or /replace to swap document

app/api.py
  - POST /ingest (multipart file)
  - POST /chat {question}
  - GET /health


--------------------------------------------------------------------------------
7. VECTOR STORE
--------------------------------------------------------------------------------

Collection: pdf_chat
  - Vectors: MiniLM (384-d)
  - Payload: text, page_start, page_end, source_name, unit, chunk_id
  - Distance: cosine
  - Lifecycle: deleted + recreated on every successful ingest

  CHUNK_SIZE=1200
  CHUNK_OVERLAP=150
  TOP_K=5
  MAX_FILE_MB=25
  CHAT_HISTORY_TURNS=6

  OCR_ENABLED=true
  OCR_MIN_CHARS=40
  OCR_DPI=200
  OCR_EMBEDDED_IMAGES=true

9. HOW TO RUN
--------------------------------------------------------------------------------

From DocChat_RAG/:

  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements.txt
  cp .env.example .env          # set GROQ_API_KEY
  docker compose up -d          # Qdrant on :6333

  PYTHONPATH=. chainlit run app_ui.py --host 0.0.0.0 --port 8000
  # open http://localhost:8000

Optional API:
  PYTHONPATH=. uvicorn app.api:app --host 0.0.0.0 --port 8001

Tests:
  PYTHONPATH=. pytest -q

--------------------------------------------------------------------------------
12. FAILURE MODES / LIMITS
--------------------------------------------------------------------------------

  - Empty / image-only PDF with failed OCR → ingest error
  - File larger than MAX_FILE_MB → rejected
  - Missing GROQ_API_KEY → chat fails; UI warns on start
  - Qdrant down → UI warns on start
  - One document only — uploading replaces previous index


--------------------------------------------------------------------------------
13. CHAT HISTORY
--------------------------------------------------------------------------------

  Chainlit built-in `cl.chat_context` accumulates every user/assistant
  message in the session. On each question we call:

      history = cl.chat_context.to_openai()

  and pass recent turns into Groq together with fresh RAG context.

  - Tunable: CHAT_HISTORY_TURNS (default 6 pairs)
  - Cleared on new document ingest (`cl.chat_context.clear()`)
  - Follow-ups like "explain that more" can use prior turns


--------------------------------------------------------------------------------
14. MENTAL MODEL (ONE SENTENCE)
--------------------------------------------------------------------------------

  Document → extract text (+ OCR) → chunk → MiniLM → Qdrant;
  Question + chat history (cl.chat_context) → retrieve text → Groq.
